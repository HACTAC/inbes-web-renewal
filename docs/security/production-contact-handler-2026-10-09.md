# 本番フォーム送信処理の実装候補

## 実装候補

両フォームの入口は文脈別のまま、共通の送信処理へ接続する。デザインは維持する。[移行計画](production-migration-plan-2026-10-09.md)の未実装ブロッカーを解消するための候補であり、現在は公開・SMTP接続とも未実施である。

- [送信処理](../../server/contact/send.php): 同一オリジン・期限付きセッショントークン、単回使用、入力検証、連続送信制限、SMTP経由の管理者通知。
- [入力・添付検証](../../server/contact/FormRules.php): 種別の固定選択、同意必須、文字数・UTF-8・ヘッダー制御文字の検証、添付1点10MB以内、拡張子とMIME照合。添付はPHP一時ファイルを使用し、公開領域へ保存しない。
- [UI](../../src/components/ContactForm.astro): トークン取得成功後だけ送信可能。送信中、受付完了、入力エラー、利用停止、送信回数超過、結果不明を区別する。
- 自動返信は設定で明示的に有効化した場合だけ送る。問い合わせ通知の受付後に自動返信が失敗しても、問い合わせを再送させない。
- 応答喪失・SMTP受付結果不明の場合は送信を再び有効化せず、重複送信を避ける案内を表示する。
- PHP 8.2以上と必要な拡張を前提とする。メール生成・SMTPは[PHPMailer公式](https://github.com/PHPMailer/PHPMailer)を使い、独自SMTP実装やPHP mail()へフォールバックしない。

## 濫用対策と限界

同一オリジン検証とCSRFトークンは、他サイトからの通常ブラウザ投稿を制限するが、人間とbotを区別するものではない。ハニーポットと、送信元IP単位5件/時・全体100件/時の上限を併用する。IPはHMACで識別し、制限状態は公開領域外に保存する。プロキシ由来の任意ヘッダーは信頼せず、REMOTE_ADDRを使う。

本番がプロキシ経由の場合はREMOTE_ADDRが共有され、制限が全利用者へ作用する可能性がある。実接続経路を確認する。共有IPによる誤制限、分散botによる上限消費、メール到達の保証がないことは残る限界である。必要なら信頼プロキシ設定や人間確認を別途レビュー・承認して追加する。

添付は種類・サイズの検証であり、マルウェアの無害化ではない。受信側での検査を必要とする。POST上限は添付10MBに本文・multipart overheadを加味した値、upload_max_filesizeは10MB以上が必要である。

## フォーム停止

フォーム有効化前の設定を退避し、問題時はenabledをfalseへ戻して新しい受付を止める。停止は処理中のメールを取り消さない。送信済みのメールは復元操作で取り消せない。

サイト全体を旧版へ戻す手順とフォームを停止する手順を分離し、いずれも公開時の明示承認範囲に含める。非公開設定や資格を無断削除しない。
